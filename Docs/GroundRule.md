## 2. 회의 일정

### 일일 회의
오전 9시에 10분간 일일 업무 회의를 진행

#### 회의 내용
- 금일 진행 업무
  - 작업하고 있는 영역을 공유해서 ***다른 팀원과 동시에 작업이 진행되서 충돌이 나는 사태를 방지***합니다.
  - 진행하고 있는 작업의 시작일과 마감일을 공유해서 개발일정에 차질이 없는지 확인합니다.

### 기획 회의
게임 기획적인 회의가 필요할 때 ***비정기적***으로 일정을 잡아서 진행합니다.
- 프로젝트 기능 명세 수정
- 게임 레벨디자인 수정  

## 3. 개발 가이드

### 코딩 컨벤션
- [코딩컨벤션](https://github.com/swchoi-dev/PracticeTeamProject/blob/prod/Docs/CSharpConvention.md) : 해당 문서의 내용을 기준으로 코딩 컨벤션을 정의합니다
- [코드정리자동화](https://github.com/swchoi-dev/PracticeTeamProject/blob/prod/Docs/%EC%BD%94%EB%93%9C%EA%B7%9C%EC%B9%99%EC%9E%90%EB%8F%99%ED%99%94.md) : 해당 문서의 내용을 적용하여 코딩 컨벤션의 어긋나는 부분을 경고표시 및 자동 수정이 되도록 합니다.

### 커밋 가이드
- feat : 기능 추가, 변경, 삭제 등 개발에 대한 전반적인 내용
- fix : 개발 진행 중 Bug Issue 티켓에 대한 내용일 경우
- docs : 문서작업을 했을 때
- chore : 코드컨벤션 맞춤, 기타 작업 시

### 브랜치 가이드
- main : 게임의 빌드를 생성할 운영 브랜치입니다. 모든 신규브랜치는 여기서 생성합니다.
- feature : 깃헙 이슈페이지에서 Create Branch 버튼을 통해 만들고 prod 브랜치로부터 생성합니다. 브랜치 명은 feature-이름-기능 으로 정합니다. (ex-feature-swchoi-player_구르기_기능_추가)
PR 생성 후 머지된 feature 브랜치는 삭제합니다.

## 4. 이슈 해결

### 개발하다 도움이 필요할 때
1. 깃헙 이슈 페이지에 댓글로 무엇이 안되는지 작성하고 슬랙으로 내용을 공유합니다.
2. 해결 방법을 아는 팀원이 깃헙 이슈 페이지에 댓글로 내용을 작성합니다.
3. 팀원 모두가 해결 방법을 모르면 **강사님에게 힌트를 달라고 도움을 요청합니다.**

### 버그를 발견했을 때
1. 머지가 완료되고 브랜치가 삭제된 기능에 버그가 발견되는 경우
2. 깃이슈에 버그 타입으로 이슈를 생성하고 담당자에게 할당해줍니다.
3. 머지가 되지 않은 개발 중인 기능에 버그를 발견한 경우, 깃 이슈에 댓글로 달아서 공유합니다.

### 충돌이 났을 때
1. 팀장에게 공유합니다.
2. 팀장이 **해결하기 어려운 충돌**이거나 개발 일정으로 바쁜 경우라면 
3. 바로 **강사님에게 도움을 요청합니다.**

### 작업 일정 조정이 필요할 때
1. 깃 이슈에 작업 일정 조정이 필요한 이유와 조정을 원하는 일정을 댓글로 작성합니다.
2. PM에게 공유 후 PM의 의사결정을 따릅니다.
